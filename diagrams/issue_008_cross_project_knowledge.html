3 🤖 Copilot Studio Agent Generative
🛠️
Build Steps
1 Create new agent
2 Add Azure AI Search as knowledge source
3 Enable generative answers
4 Paste cross-project system prompt
📝
Custom System Prompt
The key to cross-project synthesis:
"When answering, search across all projects. If you find related decisions in different projects, explicitly connect them and cite both sources. Always state which projects your answer draws from."
⚙️
Zero Custom Code
No code in Copilot Studio itself. Intelligence lives in the index — agent is a thin conversational layer.

4 🔌 Plugin Action — "Index this conversation" User-fed Knowledge
📋
User Workflow
User exports a Copilot / Claude / ChatGPT conversation, pastes the transcript into the agent, and invokes the plugin action — turning an ephemeral chat into durable, searchable knowledge.
⚡
Power Automate Cloud Flow
Exposed as a plugin action. Parses the conversation, runs the same Azure OpenAI enrichment as Step 2, indexes into the same Azure AI Search instance — same schema, same retrieval.
🔁
Closes the Loop
Users actively feed the system. The longer the agent runs, the richer its cross-project memory becomes — even when source documents were never written down formally.
🪶 Trivially Simple Agent
The agent itself is generative answers pointed at a search index. All the intelligence lives in the enrichment pipeline — not the agent. Build the hard part once, get a working agent on Day 1.
🗓️ Demo in a Day
Pick 2 SharePoint sites · manually enrich 20 docs · create the AI Search index · stand up Copilot Studio agent with the cross-project prompt · ask the "impossible" question. Customer sees value the same day.
🔑 The Key Field: related_artifacts
Every doc carries pointers to other docs it relates to — even across projects. That single field turns siloed search into cross-project synthesis. Without it, the agent answers in one silo; with it, it traverses them all.
